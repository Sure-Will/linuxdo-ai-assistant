# Linux.do AI 阅读助手

Chrome 标签页和 Linux.do PWA 共用的油猴脚本。使用自己的 Chat Completions 兼容模型，提供流式总结、连续追问、上下文选择和本地对话历史。

仓库：[Sure-Will/linuxdo-ai-assistant](https://github.com/Sure-Will/linuxdo-ai-assistant)。安装地址（Mac 与 Windows 通用）：

```text
https://raw.githubusercontent.com/Sure-Will/linuxdo-ai-assistant/main/dist/linuxdo-ai.user.js
```

## 安装（Mac 与 Windows 相同）

1. 在创建 Linux.do PWA 的同一个 Chrome 个人资料中安装 [Tampermonkey 官方版](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo)。
2. Chrome 扩展详情中开启 Tampermonkey 的“允许用户脚本”。不同 Chrome 版本的入口见 [官方说明](https://www.tampermonkey.net/faq.php?q=Q209)。
3. 在 Chrome 中打开上面的安装地址，Tampermonkey 会显示安装页，点击“安装”。
4. 刷新 Linux.do PWA 的页面。右侧阅读器按钮旁会出现星芒图标，悬停显示“AI 总结”；窄窗口没有右侧工具栏时，入口位于右下角。
5. 打开面板后，点击右上角“更多操作”中的“模型设置”，填入 API Key 并保存。仅在手动点击发送按钮时调用模型；留空总结，有文字则提问。

日常运行只需要这个 `.user.js` 文件，无需 Node.js、终端或本地服务。

**从手动粘贴的旧版本切换**：已用复制粘贴方式安装过的电脑，打开安装地址后 Tampermonkey 会显示“更新”。名称和 namespace 不变，会覆盖原脚本并保留原有设置与历史；之后即可自动更新。

## 多台电脑同步

- **脚本**：安装文件带有 `@updateURL` 与 `@downloadURL`，指向 `main` 分支。推送新版本后，各电脑的 Tampermonkey 会在下次检查时自动更新（默认每天一次）；想立即更新，在 Tampermonkey 菜单中选择“检查用户脚本更新”。GitHub 原始文件有几分钟缓存。
- **设置与历史不同步**：API Key、模型、思考强度、面板大小和对话历史保存在每台电脑各自的 Tampermonkey 存储里。新电脑需要在“模型设置”中填写一次 API Key，密钥不会上传到仓库或其他云端。
- **在另一台电脑上开发**：克隆仓库即可，构建只需要 Node.js；只使用脚本不需要克隆。

## 模型设置

- 内置供应商为 DeepSeek 官方，地址为 `https://api.deepseek.com/chat/completions`，默认模型为 `deepseek-flash`，也可选择 `deepseek-v4-pro`，或选择“自定义模型名”直接填写模型 ID。模型名依据 2026-09-30 核对的 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。
- 设置内的“模型测速”使用当前填写的地址、Key 和模型，不需要先保存。它只发送一次固定短提示，不读取帖子、不写入对话或自动保存草稿；可随时停止，退出设置也会取消。DeepSeek 测速关闭思考。显示首字耗时、生成速度和总耗时；速率优先使用服务端返回的 token 数，没有用量时明确显示字符/秒，一次性缓冲响应不显示流式速度。
- 选择“自定义”后可填写其他 Chat Completions 兼容接口。API 地址支持 Base URL 或完整的 `/chat/completions` 地址，Base URL 会自动补上 `/chat/completions`。
- 已有自定义地址、模型和对话保留；切换供应商时清空表单中的 Key，避免将原供应商密钥带入另一家。
- API Key 使用 Tampermonkey 的本地脚本存储，脚本不访问 macOS 钥匙串，也不写入 Linux.do 的 `localStorage`。该存储不是系统级加密保险箱。
- 模型请求只发送到你配置的地址。跨域通过 `GM_xmlhttpRequest` 处理，不向模型服务发送论坛 Cookie。
- DeepSeek 官方域名通过 `@connect api.deepseek.com` 显式声明。额外的 `@connect *` 用于自定义服务商的连接确认，不表示所有域名已自动获准。脚本本身仅匹配 `https://linux.do/*`。若油猴要求确认 API 域名权限，只允许自己配置的服务商。

## 使用

- 打开、重开面板、刷新和切换话题都不自动读取帖子或总结。底部只保留一个发送按钮：输入留空时总结，有文字时发送问题。
- 输入框下方的范围按钮可选“仅首帖、前 5 / 10 / 20 帖、全部帖子”，默认前 5 帖，计数包含首帖。
- 范围按钮直接展开可选项，无需再打开二级选择框。旁边的思考强度提供“关闭、低、高、最高”，DeepSeek 默认高，分别使用 `none / low / high / max`，配合 `thinking.type` 开关。依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [Chat Completions 参数文档](https://api-docs.deepseek.com/api/create-chat-completion/) 于 2026-09-30 核对。通用自定义接口另有“默认”，不附加思考参数；是否支持其他档位由接口决定。
- 回答上方显示本条消息生成时使用的模型名；之后切换模型不改变旧回答署名。
- 模型返回思考内容（`reasoning_content` 或 `reasoning`）时，回答上方显示“思考过程”：思考阶段自动展开并流式显示，正文开始后收起为“已思考 N 秒”，点击可展开回看。思考内容随对话保存在本地，追问时不会发回模型。
- 范围菜单内的“更新原文”仅刷新帖子上下文，不调用模型。实际篇数收在同一菜单里。
- 追问会携带当前范围的原文和完整问答历史。停止或失败的半条回答仍保留在界面，但不作为完整答案送进下一轮。
- `Enter` 发送，`Shift + Enter` 换行；中文输入法选词时回车不发送，仍兼容 `⌘ + Enter` 和 `Ctrl + Enter`。`Esc` 返回对话或关闭面板。
- 右上角“更多操作”收纳新对话、历史和模型设置。“新对话”保留旧记录；“历史”查看本话题的其他对话。历史属于当前浏览器个人资料，不上传云端。
- “更多操作”右侧的“导出图片”把当前对话生成 PNG，版式参照 FluxDO：话题标题、提问与 AI 回复（含模型名）、生成时间和话题链接。可选浅色或深色背景，复制到剪贴板或保存到下载目录。只导出完整的问答，不含思考过程；只有一次总结时只保留回答。图片在本地生成，不上传。
- 生成时视图不自动滚动：新问题滚到顶部，回答在下方原地生成，可随时停在任意位置；点击“回到最新”只跳转一次。生成中选中文字时暂停刷新，取消选择后补上。
- 每楼收藏后的常驻图片按钮可直接把楼主帖或任意回复导出为图片，版式参照 FluxDO 的帖子分享图：话题标题、作者头像与昵称、正文、楼层链接。点击时才读取这一楼的 `/posts/{id}.json`；正文按白名单重建，图片、emoji 和头像下载后缩放并画进图里（最多 12 张），读不到的图片显示占位，视频、投票和嵌入内容显示为文字占位，剧透不展开。图片在同站或允许跨域时直接读取，否则经油猴请求，首次访问新的图片域名时油猴会询问是否允许。
- 普通话题的帖子操作栏默认从左到右保留“点赞、回复、收藏、图片分享、Boost、更多”六个图标；回复不显示文字，图标与其他按钮同宽居中，保留悬停提示和无障碍名称。点击“…”后，复制链接、举报及有权限时的编辑、删除等原生图标在原行横向展开，更多按钮随之隐藏；点击外部或使用操作后仍保持展开，刷新或切换话题后恢复默认，新加载的楼层仍默认收起。Boost 沿用原站按钮和显示条件；未登录、没有权限或原站不提供的按钮不补造。私信仍保留原站操作栏和复制链接旁的图片按钮，避免初始化时触发已读名单请求。
- 关闭面板只是隐藏，已开始的读取和生成在后台继续，重新打开可看到进度或完整回答；需要中断时点停止按钮。切换话题或离开页面会取消当前请求。除你主动发起的这一次请求外，不会在后台自动浏览、总结、重试或发帖。
- 模型返回的 Markdown 通过白名单 token 创建 DOM。原始 HTML 不执行，图片只显示链接，不自动加载。

## 边界

- 首版为文字总结与追问，不包括图片识别和 FluxDO 原有历史迁移。
- 所选原文超过 12 万字符会要求缩小范围；含历史的请求超过 18 万字符会要求新建对话或缩小范围。实际模型可能有更小的上下文限制，服务商报错会显示在面板中。
- 论坛缺少楼层、要求登录或 Cloudflare 验证时，不把不完整数据发送给模型；在正常 Chrome 页面完成验证后再试。
- 卸载脚本或清空其油猴存储会影响本地配置与历史。仅禁用脚本即可暂时恢复原站界面。

## 开发与验证

```sh
npm run build
npm test
npm run test:browser
```

构建脚本使用 Node.js 标准库，将源码、CSS 和已随项目保存的 Markdown 分词库合并成一个安装文件。浏览器测试需要 `playwright-core` 和 Chromium；可以用 `NODE_PATH` 指向已安装模块，用 `CHROMIUM_EXECUTABLE` 指向已有 Chromium 可执行文件。

`npm run preview` 会打印一个 `/preview` 地址，打开后可切换空白、对话、生成中、错误、设置，以及明暗主题与窄屏。预览直接加载当前构建的安装脚本，使用独立的模拟存储和模型响应，不访问真实服务。服务只监听 `127.0.0.1`，仅供 UI 打磨，日常使用脚本不需要运行。源码修改后重新构建，预览会在一秒内自动刷新；“改前”按钮加载 `test-results/preview/baseline.user.js`（本地生成，不提交），用于对比改动前的界面。

发布新版本（Tampermonkey 只在 `@version` 变高时更新，忘记升版本号两台电脑都不会更新）：

1. 修改 `package.json` 的 `version`。
2. 运行 `npm run build`、`npm test`、`npm run test:browser`。`npm test` 会检查安装文件的版本号与 `package.json` 一致，防止推送过期的构建。
3. 提交并推送到 `main`。

源码布局：

- `src/core.js`：上下文读取、消息构造、SSE 与模型请求。
- `src/render.js`：安全 Markdown 渲染与帖子文本提取。
- `src/app.js`、`src/style.css`：面板、路由、交互和存储。
- `test/`：协议测试、浏览器测试和可见的模拟验收页。
- `dist/linuxdo-ai.user.js`：安装文件。
